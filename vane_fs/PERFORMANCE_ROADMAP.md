# VaneFS 性能收尾路线图

执行起点：`5c8c06322494d67c8469161b14c3665c69b61acf`。
本文件是本轮执行清单；每个阶段完成后更新证据和决定，不再以不断增加实验为完成标准。

## 交付目标和边界

交付一个可审查的本地 C++ VaneFS 版本，保留分支、快照、合并、GC、Linux FUSE 和本机 Vane 查询能力。
默认数据库格式、现有工作空间兼容性和持久化语义保持不变。默认实现与隔离实验的成绩分别报告。

本轮另外对两个已定位的性能问题做有限验证：大文件末尾 payload 落盘积压，以及写入路径中的 checkpoint 停顿。
外置 payload 格式 1005 的实验即使性能通过，也不能自动取代默认格式；迁移和发布兼容性没有完成时，结果只作为后续版本的采用依据。
远程／嵌套 filesystem、S3、多机、可写 mmap、新格式迁移不加入本轮。

## 固定规则

1. 从本文件建立后起，最多 **3 个候选实现**：预写回最多 2 个，checkpoint 最多 1 个。名额是上限，不要求用完。
2. 每个候选只改变一个机制，最多一次针对性诊断和一次正式配对验收。已获得充分诊断的机制直接进入验证。
3. 失败样本保留；不能以负载不稳为由反复重跑、删样本、改门槛或重新选择对照。
4. 构建／测试／分析与正式测量串行；只运行相关测试。每次结束清理已停止进程拥有的数据，保留身份、配置、日志和测量证据。
5. 正确性失败先淘汰性能结论；修复测试设施不算新候选，但必须保留失败和证明原生实现未改变。原生策略改变消耗新名额。
6. 候选不通过时恢复既定基线。预算用完或没有有依据的下一方案时，直接进入最终验收，不再开启新调查分支。
7. 本轮结束后，继续优化需要新的独立目标和预算。其他项目的成绩仅作参考，不构成交付门槛。

## S1：版本和既有成果

默认实现的源码以本轮起点冻结，内容保存在 SQLite `block_payloads` 中。已有工作空间支持格式 1／2；fsync 模式升级使用兼容的 barrier 表。
以下改进已进入默认原生实现，不需要重新作为新候选研究：

| 已采用机制 | 引入提交 |
| --- | --- |
| 减少块 I/O 的 SQL 开销 | `87b3892943` |
| 挂载租约下的元数据缓存 | `98b0fe44c6` |
| 减少重复 inode 引用持久化 | `9ee791a625` |
| WAL checkpoint 同步摊销 | `49545265f8` |
| 延迟并批量列举目录 | `08535e6e53` |
| 可选 fsync 持久化模式 | `f40c57742e` |
| 后台 checkpoint 边界和背压 | `0fc47514e4` |
| 空块区间批量写入 | `7cccaf814f` |

外置 payload、extent、预写回、BEGIN/RESTART gate 等实验都没有自动纳入默认实现。
实验报告中的 `status=PASS` 通常表示验证／审计成功，不能解释为性能验收成功或已经采用。
[最近配对验收](benchmarks/staged_payload/begin_gate_matched/README.md)仍有 **9/22 项失败**；
[原生归因](benchmarks/staged_payload/gate_sync_waits/README.md)确认两次长 fsync 的 99.5%／99.9% 在实际 payload fdatasync 中，另有一次前台 PrepareExternal PASSIVE checkpoint 耗时 906 ms。

实验固定对照采用已有的 **format 1005 paced parent**：64 MiB 预写回触发、4 MiB 有限请求、16 ms 完成后间隔、FULL pause。
未通过的 BEGIN/RESTART gate 不带入新对照。其问题和失败记录继续保留。
默认实现是交付基线；上述隔离版本只是机制实验对照，两者不能混称。

盘点记录：[inventory.json](benchmarks/performance_closeout/inventory.json)。默认源码未修改；48 个隔离实验逐项记录报告身份和采用状态。

## S2：预写回候选

**C1：提前启动有限预写回。** 对固定实验对照，仅将 owner-local 触发从 64 MiB 改为 16 MiB。
保持每次 4 MiB、16 ms 间隔、有限物理范围、独立 GC 租约、FULL pause、失败传播及实际 payload／WAL／fence 同步不变。
已有证据是 64 MiB 阶段在最终 fsync 前只有一次 4 MiB 提示；这支持测试提前启动，但不保证性能改善。

**C2：条件名额。** 仅当 C1 的结果支持一个具体、不同的积压调度假设时使用。
不进行阈值或间隔网格搜索；没有新依据就标记为“不使用”，直接推进 S3。

## S3：checkpoint 候选

**C3：条件名额。** 检查能否把 BeforeWrite 中的可选 CLEAN-prefix 预处理移出请求关键路径。
只处理这一机制，不同时重写后台 RESTART。需要先证明保留 OPEN 发布顺序、跨连接／进程保护、PASSIVE 进度、FULL 绕过和 64 MiB WAL 准入边界。
不能满足这些条件时记录“不实施”，不扩展为新的存储协议设计。

## 固定验收

实验性能沿用已有的 22 项完整验收：fresh 和 GC 后各 6 组 AB/BA 配对，持续写入另做每状态 2 组、每工作空间 4 个周期。
使用相同工作负载、SDK、持久化模式、对照源码和最终 fsync／close 计时。大文件组合完整吞吐目标仍为至少 10%；随机 I/O、目录、生命周期及请求长尾沿用原检查的退化容忍值。
不只看中位数；保留聚合耗时、p99、最大值、所有超过 1 秒的操作及其出现次数。短样本未重现停顿不构成延迟上限。

复用冻结的 `begin_gate_matched` 工作负载和 `paced_range_writeback/analyze.py` 检查逻辑。
报告必须分别给出“运行成功”“正确性通过”“性能通过”“可纳入默认实现”四种结论。
任何隔离实验不满足兼容／发布条件时，不得因为性能数字好就写成默认实现已加速。

S4 的默认实现验证使用实际默认二进制；实验完整矩阵可以作为 S4 的候选证据复用，避免相同输入下再跑一遍。
默认源码和二进制未改变时，已有相关测试按精确身份继承；不继承另一个格式的测试结论。
